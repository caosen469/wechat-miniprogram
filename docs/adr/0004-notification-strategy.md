# 通知与提醒策略：一次性订阅消息推送 + 站内红点兜底

个人主体小程序无法使用长期订阅消息，只能用一次性订阅（授权 1 次 = 可发 1 条，T9 调研）。即便如此，我们决定 MVP 就做微信推送而非只靠自然打开：家庭圈里最需要触达的父母恰恰是最不主动打开小程序的人，而推送的增量成本很低。形态上以「站内红点」为兜底——推送是增强不是依赖。

具体策略（grilling 决议，T10）：

- **内容**：作者昵称 + 地点名 + 吐槽首句截断，点击直达该记录详情页。订阅消息模板字段放不了照片缩略图。
- **节奏**：每条即推，不做摘要（一次性订阅「1 次授权 = 1 条」使摘要无意义，且家庭圈低频）。唯一聚合：同一人 1 分钟内连发多条只推最后一条。
- **授权**：发布成功后引导一次（动机最强的时刻，引导勾选「总是保持以上选择，不再询问」），设置页留常驻开关；此后每次打开小程序在自然点击点**静默续授权**攒额度（已勾选后不再弹窗）。
- **降级**：额度耗尽（错误码 43101）时静默失败，不提示发布者「谁没收到」——家庭场景要避免制造社交压力。若「家庭内容提醒」类模板审核不过，MVP 以纯红点形态先上线，推送留接口后补，不阻塞开发。
- **隐私**：「仅我俩」的记录推送用模糊文案（「你的另一半发了一条仅你可见的动态」，不带地点不带摘要），防止推送文案在微信「服务通知」里泄露私密内容；「仅自己」的记录不触发任何推送。
- **权限联动**（由 T4 权限模型推导）：推送发送在云函数收口处按可见范围过滤——退出/被移除的成员不推，「仅我俩」不推第三人。

## Considered Options

- 完全不做通知、靠自然打开：最省事，但放弃触达父母这一核心场景。
- 只做站内红点、无推送：零审核风险零授权成本，但用户不打开小程序就看不见，等于没通知。

两者都因「触达不主动的用户」被否决。
