# 家庭圈账号与权限模型：单圈 + 圈主 + 邀请码，「能看见就能编辑/删除」

整个小程序服务**一个家庭圈**（不做多租户）：项目所有者注册时创建圈子并成为**圈主**——唯一的特殊角色。成员凭圈主生成的**邀请码**入圈；成员可自行退出，圈主可移除成员；退出/移除后历史记录保留，但不可再看不可再改。私密可见性（「仅我俩」）由圈主指定的**固定二人组**承载，且每条私密档记录落库时**固化当时二人组两人的 openid**——将来重指另一半，新搭档看不到旧记录。权限规则三档统一：**能看见就能编辑、能删除**，不设审核。

## Considered Options

- **任意成员对可见性（否决）**：把三档可见变成「任意成员子集」，过滤与 UI 复杂一个量级；实际只有情侣二人用得到。
- **私密档随当前二人组走（否决）**：重指另一半后，新搭档能看到旧搭档的私密记录，隐私上不可接受。
- **编辑/删除仅作者 + 管理员（否决）**：家庭圈内是信任关系，规则越单一越好记；「能见即可改/删」一句话说清，数据层无需特判。
- **多圈模型（否决）**：实际使用者就是固定的 4–6 人，多圈徒增路由、列表与邀请复杂度。

## Consequences

- 成员表需要 `status: active | left | removed` 表达成员生命周期；查询可见内容时始终按 `active` 过滤。
- 私密档记录多存一个 `pairIds` 字段（创建时的二人组 openid 快照），过滤条件：请求者 ∈ `pairIds`。
- 邀请码是一个带过期时间的文档：6 位口令、24 小时有效、可重复使用、圈主可随时作废；实现上限成员数（如 12）防滥用。
- 圈主不可退出、MVP 不做转让；成员显示名与头像入圈时用微信「头像昵称填写能力」自填。
- 上传权限全员（在圈成员）平等，无审核环节。
