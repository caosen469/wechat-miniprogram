## 1. 项目概述与目标用户

### 1.1 一句话

一个给**一个家庭圈（4–6 人：你、女友、双方父母）**共用的生活记录小程序：去哪儿玩、吃了什么，拍下来、打个分、吐个槽，攒成家庭共同的回忆地图。

### 1.2 核心能力（MVP 范围）

| 能力 | 说明 |
|---|---|
| 打卡发布 | 在某地点创建一条「回忆记录」：图片 ≤9 张 + 视频 ≤3 段（每段 ≤60s，可混搭）+ ≤500 字吐槽 + 0–1 段 ≤60s 语音 + 1–5 星评分 |
| 地点归并 | 同一家店多次到访自动归并到同一「地点」，综合评分与到访次数由记录汇总派生 |
| 分层可见 | 默认家庭圈共享；「仅我俩」私密档；「仅自己」私密档 |
| 足迹浏览 | 足迹列表（地点为一等公民）+ 可切换的地图视图（一店一 marker）+ 相册式详情 |
| 弱网可靠 | 旅行弱网/离线也能打卡，本地排队、联网自动补传 |
| 家庭提醒 | 新记录经微信订阅消息推送 + 站内红点兜底 |

**明确不做**（决议见地图 Out of scope 与各 ADR）：旅行合集 UI（记录预留可选字段）、点赞/评论、批量导入历史相册、多家庭圈、用户侧数据导出功能、年度统计、摘要/定时通知。

### 1.3 裁剪线：本 spec 写到哪、哪些留给编码

**写死在本文档**（返工成本高，提前锁）：

- 数据库全部集合的**字段表**（第 4 章）
- 云函数**清单与职责**（第 5 章）
- 每个页面的**信息项与交互规则**（第 6 章，含草稿策略）
- 弱网队列与通知的**行为规则**（第 7、8 章）
- 实现**阶段划分与验收标准**（第 9 章）

**留给编码时再定**（对着原型和本文档现场决策即可）：

- 组件拆分与 wxml/wxss 结构、样式与视觉细节
- 代码文件组织、工具函数抽取、命名
- 数据库索引的具体建法（第 4 章只给必须索引的字段名）
- 动画与过渡效果
- 具体文案措辞（除少数有功能语义的，如降级时的静默规则）

## 2. 技术基线与整体架构

### 2.1 技术栈（已定，不再讨论）

- **微信小程序原生框架**（不用 uni-app/Taro，减少一层抽象）
- **微信云开发 CloudBase**：云数据库（文档型）+ 云存储 + 云函数，不自建后端（[云开发能力调研](../research/cloudbase-capabilities.md)）
- **内置 `<map>` 组件** + 腾讯位置服务个人开发者免费额度（[地图组件调研](../research/map-component.md)）

### 2.2 架构总原则

**全部数据读写经云函数收口，小程序端不直连云数据库**（ADR [0003](../adr/0003-cloud-function-gates-all-data-access.md)）：

```
小程序端（页面/组件）
   │  wx.cloud.callFunction
   ▼
云函数层（每个函数先鉴权：openid → 查成员身份与状态 → 可见范围过滤）
   │  服务端 SDK
   ▼
云数据库（members / places / records / ...） + 云存储（媒体文件）
```

为什么不用数据库安全规则：三档可见性 + `pairIds` 快照 + 成员状态的复合过滤，安全规则表达式写不了，硬写必漏；云函数收口让鉴权集中一处、可调试，也是弱网队列和通知过滤的统一入口。代价是每次操作多一跳——4–6 人量级可忽略。

**媒体走云存储直传**：小程序端 `wx.chooseMedia` 选完 → `wx.cloud.uploadFile` 直传云存储 → 拿到 `fileID` 后随记录数据一起提交给云函数。媒体不经云函数中转（省内存、省流量）。

### 2.3 身份与登录

零开发：云函数调用时自动注入调用者的 **openid**（免 `code2Session`），openid 即成员唯一标识。头像昵称用微信「头像昵称填写能力」由成员自填（见 6.6）。

### 2.4 成本预期（[调研详情](../research/cloudbase-capabilities.md)）

- 免费额度（约 5GB 存储 + 5GB/月 CDN 流量 + 每日万级数据库读写 + 40 万资源点云函数）对 4–6 人家庭**完全够用**
- 超量后月成本约 5–10 元；个人版套餐 19.9 元/月
- 腾讯位置服务个人开发者基础免费
- 不设止损线：已查实历次调价有 1 个月缓冲，数据可全量导出走人（见 10.5 导出 runbook）

## 3. 领域模型与术语

完整术语表见 [`CONTEXT.md`](../../CONTEXT.md)（开发全程保持最新）。核心概念速览：

- **回忆记录**：一次地点到访的完整记忆——产品的基本单位。锚定「一次到访」，不是一次旅行一条，也不是一张照片一条（ADR [0001](../adr/0001-memory-record-anchors-one-visit.md)）。
- **地点**：独立实体，同店多次到访共享；类型挂地点上、首打卡选定后继承；均分与次数是派生值，不落库。
- **评分** 评的是「这一次」；**情绪档位**（宝藏 4–5★ / 还行 3★ / 踩雷 1–2★）由评分映射，不单独录入。
- **家庭圈 / 圈主 / 邀请码 / 另一半**：权限模型术语，见 ADR [0002](../adr/0002-family-circle-account-and-permission.md)。
- **提醒**：新记录的订阅消息通知；私密档只发模糊文案，仅自己档不发（ADR [0004](../adr/0004-notification-strategy.md)）。

## 4. 数据库设计

文档型数据库（类 MongoDB），4 个业务集合 + 1 个圈子集合。字段表是锁死的；索引只列字段名，建法编码时定。

### 4.1 `circles` — 家庭圈（全库仅一条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `ownerId` | string | 圈主 openid |
| `pairIds` | string[2] | **当前**「另一半」二人组 openid。仅用于新记录固化快照与圈主重指；修改不影响历史记录 |
| `createdAt` | datetime | |

> 阶段 1 第一个用户创建圈子时生成此文档，自己成为圈主。

### 4.2 `members` — 成员

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `openid` | string | 唯一索引 |
| `nickname` | string | 入圈时自填 |
| `avatarUrl` | string | 云存储 fileID（头像昵称填写能力上传） |
| `role` | string | `owner` \| `member` |
| `status` | string | `active` \| `left`（自退）\| `removed`（被移除） |
| `joinedAt` | datetime | |
| `leftAt` | datetime | 退出/移除时间，仅退出后有值 |
| `lastReadAt` | datetime | 红点水位：最后已读时间。新记录数 = `records.createdAt > lastReadAt` 且可见 |

> 退出/被移除成员的**记录保留**（不可见不可改）——靠查询时按 `status: 'active'` 过滤，不删数据（ADR 0002）。

### 4.3 `invite_codes` — 邀请码

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `code` | string | 6 位口令，唯一索引 |
| `createdAt` | datetime | |
| `expiresAt` | datetime | 创建后 24 小时 |
| `revoked` | boolean | 圈主可随时作废 |
| `createdBy` | string | 圈主 openid |

> 可重复使用（多人凭同一码入圈）；成员上限 12 在云函数校验。

### 4.4 `places` — 地点

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `poiId` | string \| null | 选点通道返回的 POI 唯一 id。**归并键**：非空时同 poiId 视为同店；poiId 未命中（含 null 手动地点）时再按**同名精确归并**（2026-08-15 真机反馈调整，替代原「手动地点不归并」约定） |
| `name` | string | |
| `type` | string | `restaurant` \| `attraction` \| `accommodation` \| `other`。首打卡时选定，后续到访自动继承 |
| `location` | geopoint | 经纬度 |
| `coverFileID` | string \| null | 封面图（最新一条记录的首图，更新记录时顺带刷新） |
| `createdBy` | string | 首打卡者 openid |
| `createdAt` | datetime | |

> **派生值不落库**：均分、到访次数、情绪档位分布每次由云函数从 records 聚合得出（量级小，无需缓存）。
> **地点生命周期**：地点在旗下**最后一条记录**被删除时一并删除；还有剩余记录则保留（2026-08-15 真机反馈）。

### 4.5 `records` — 回忆记录

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 自动 |
| `placeId` | string | 索引 |
| `authorId` | string | 作者 openid |
| `participantIds` | string[] | 参与者 openid，可空（跳过） |
| `media` | object[] | `[{fileID, type: 'image'\|'video', duration?}]`；约束：图片 ≤9 张、视频 ≤3 段且每段 ≤60s，图与视频可混搭（合计 ≤12 个） |
| `text` | string | 吐槽文字 ≤500 字（含 emoji），可为空 |
| `audio` | object \| null | `{fileID, duration}`，0–1 段 ≤60s 语音 |
| `rating` | int | 1–5 |
| `visibility` | string | `family` \| `pair` \| `private` |
| `pairIds` | string[2] | 仅 `visibility='pair'` 时固化创建时二人组快照。**重指另一半不影响旧记录** |
| `happenedAt` | datetime | 到访时间，可改（补记） |
| `collectionId` | string \| null | 旅行合集预留字段，MVP 恒为 null |
| `createdAt` / `updatedAt` | datetime | |

**必须索引**：`records.placeId`、`records.createdAt`、`members.openid`、`invite_codes.code`、`places.poiId`。

### 4.6 可见性过滤规则（所有读路径统一实现）

请求者 R 查记录，可见当且仅当：

```
R.status == 'active' 且记录满足其一：
  visibility == 'family'
  visibility == 'pair'   且 R.openid ∈ record.pairIds
  visibility == 'private' 且 R.openid == record.authorId
```

此规则在云函数层实现一次，`listFeed` / `getRecord` / `updateRecord` / `deleteRecord` / 通知过滤全部复用（ADR 0002/0003）。

## 5. 云函数设计

原则：**一个函数一件事**，函数名即接口。每个函数第一行逻辑都是鉴权（openid → 查 members → status 校验），异常统一返回 `{code, message}`。免费额度 50 个函数上限绰绰有余。

### 5.1 函数清单

| 函数 | 调用者 | 入参（要点） | 出参（要点） | 鉴权/校验 |
|---|---|---|---|---|
| `bootstrap` | 冷启动 | — | `{me, circle, members[], unreadCount}` | 任何人可调；不在圈返回 `{me: null}` |
| `createCircle` | 无圈用户 | — | 圈子信息 | 全库已有圈子则拒绝；创建者即圈主 |
| `joinCircle` | 无圈用户 | `{code, nickname, avatarFileID}` | 成员信息 | 码有效且未过期未作废；成员数 < 12 |
| `updateProfile` | 成员 | `{nickname?, avatarFileID?}` | — | active |
| `createInviteCode` | **圈主** | — | `{code, expiresAt}` | owner |
| `revokeInviteCode` | **圈主** | `{code}` | — | owner |
| `removeMember` | **圈主** | `{memberId}` | — | owner；不可移除自己 |
| `leaveCircle` | 成员 | — | — | active；圈主不可退（拒绝） |
| `setPartner` | **圈主** | `{partnerOpenid}` | — | owner；目标须为 active 成员；只改 `circles.pairIds`，不动历史记录 |
| `listPlaces` | 成员 | `{}` | 地点卡片数组（名称/类型/cover/均分/次数/情绪档位分布） | active；聚合该地点全部**可见**记录 |
| `getPlaceDetail` | 成员 | `{placeId}` | `{place, records[]}`（时间倒序） | active；可见性过滤 |
| `publishRecord` | 成员 | `{placeId 或 newPlace{...}, media[], text, audio, rating, visibility, participantIds?, happenedAt}` | `{recordId}` | active；校验媒体数量/时长/字数/星级；`pair` 档固化 `circles.pairIds` 快照；新地点时按 poiId 查重归并；成功后触发通知 |
| `listFeed` | 成员 | `{placeId?, before?, after?, limit?}` | 记录数组（含作者/参与者昵称头像） | active；可见性过滤；`before` 按 happenedAt ≤ 游标（翻页）、`after` 按 createdAt > 游标（红点条展开最新未读用，与 `unreadCount` 同水位口径，T21） |
| `getRecord` | 成员 | `{recordId}` | 记录详情 | active；可见者才返回 |
| `updateRecord` | 成员 | `{recordId, ...可改字段}` | — | active；**能看见就能编辑**（可见性过滤） |
| `deleteRecord` | 成员 | `{recordId}` | — | active；能看见就能删除；媒体文件一并删除 |
| `markRead` | 成员 | — | — | active；更新 `members.lastReadAt` |
| `sendReminders` | 内部 | `{recordId}` | — | 由 `publishRecord` 内部调用；见第 8 章 |

### 5.2 通用约定

- **错误码**：`NOT_IN_CIRCLE` / `NOT_OWNER` / `NOT_VISIBLE` / `INVITE_INVALID` / `CIRCLE_FULL` / `VALIDATION_FAILED`。前端对 `NOT_VISIBLE` 静默处理（列表里可能已被删）。
- **昵称头像联查**：返回记录时服务端 join `members`，前端不做二次请求。
- **删除记录**：云函数删除数据库文档 + 云存储媒体文件（`cloud.deleteFile`）。

## 6. 页面与交互

六个页面。浏览侧定稿 = T5 原型**变体 C**（[原型文件](../prototype/t5-map-detail-prototype.html)，落选变体 A/B 存档于 `prototype/t5-map-detail` 分支供翻案）；发布页定稿 = T8 原型**变体 C**（[原型文件](../prototype/t8-publish-prototype.html)）。

### 6.1 入圈/建圈页（onboarding）

- 无圈用户打开小程序落到此页。
- 两个入口：**输入邀请码入圈** / **创建家庭圈**（第一个用户，成为圈主）。
- 入圈/建圈时收集昵称 + 头像（微信「头像昵称填写能力」：`open-type="chooseAvatar"` 的 button + `input type="nickname"`）。
- 已在圈用户自动跳首页。

### 6.2 首页 = 足迹列表（tab 1，默认视图）

- **地点为一等公民**：足迹列表，每张地点卡片 = 封面拼图（1 图或 4 图拼图）+ 地点名 + 类型 + 均分 ★ + 到访次数 + 情绪档位徽章（宝藏/还行/踩雷，按均分映射）。
- 顶部**段控**：「列表 | 地图」切换。地图视图用 `<map>`：**一店一 marker**，`customCallout` 显示名称 + 均分 + 次数，点卡片/callout 进地点页。
- 顶部新回忆红点条：`unreadCount > 0` 时显示「N 条新回忆」，点击展开最新记录并 `markRead`。
- **空状态 = 最小引导**：一句话（如「这里还空着，去吃点什么吧」）+ 一个打卡按钮。不做任何示例内容（T6 决议：空地图是画布不是伤）。
- 右下角常驻打卡按钮（+）。

### 6.3 地点页

- 顶部统计条：总次数、平均分、情绪档位分布（三个档位的小计数）。
- 下方该地点全部记录，时间倒序，首图缩略卡。点进详情。

### 6.4 记录详情页（相册式）

- **大图翻页**为主体：横滑切媒体（图与视频混排翻页）。
- 固定的地点上下文：地点名 + 类型 + 到访序号（「第 3 次到访」）。
- 星级 + 情绪档位徽章；吐槽文字；**语音条**（播放三角 + 波形 + 时长，点击播放）。
- 元信息：作者头像昵称、时间、参与者、「仅我俩」标识（不显示给档位外的人——反正他们看不到这条记录）。
- 右上角「···」：编辑 / 删除（**能看见就能编辑/删除**，删除需二次确认）。

### 6.5 发布页（拍摄优先，T8 变体 C）

自上而下：

1. **九宫格媒体打头**：`wx.chooseMedia`（count 12，mediaType 图+视频混选；校验：图片 ≤9 张、视频 ≤3 段且每段 ≤60s，超限即时提示并拦截）。选中即持久化到本地文件（见第 7 章）。
2. **吐槽文字**：多行输入，≤500 字计数。
3. **地点内联轻选**：默认「本次不选」占位；点开选点 sheet，三个来源——
   - **POI 搜索**（`wx.choosePoi`，优先取返回的 poi id）
   - **当前位置一键打卡**（`wx.getLocation` + 腾讯位置服务逆地址/周边搜索反查最近 POI）
   - **手动新地点**（输名称 + 选类型；不参与自动归并，ADR 0001）
4. **星级内联**：5 星点选（必填才能发布）。
5. **语音条内联**：`wx.getRecorderManager`，≤60s，可重录可删。
6. **折叠区「＋更多」默认收起**：参与者多选（从成员列表）/ 可见范围 / 补记时间（默认现在，可改）。
7. **无预览步**。底栏「发布」+ 可见范围快捷入口：点开**三选一弹层**——家庭圈（默认）/ 仅我俩 / 仅自己。弹层形式防止「仅我俩」手滑。
8. 发布流程：先传全部媒体拿 fileID → `publishRecord` → 成功后清草稿、引导订阅授权一次（见第 8 章）→ 返回首页。

**草稿策略（T12 决议）**：填到一半退出（误触返回/来电话）**全量保留**——

- 媒体在**选中时**就已 `wx.saveFile` 持久化（本就是弱网队列的架构），草稿只记本地路径；
- 文字/地点/星级/语音/折叠区选项整体存 `wx.setStorage('publish_draft', {...})`，字段含 `updatedAt`；
- 下次打开发布页：存在草稿则恢复全部字段；**恢复失败的字段置空**（本地文件可能被系统清理——文件系统上限 200MB、清缓存会清掉），不弹错误、不询问，静默降级；
- 发布成功后清除草稿与对应本地文件；删除单张媒体时同步从草稿移除。

### 6.6 设置页（tab 2「我的」）

- 我的资料：头像昵称修改。
- 成员列表：头像昵称 + 状态。
- **圈主专属**：生成邀请码（展示 6 位码 + 有效期，可复制）、作废邀请码、移除成员、指定/更换另一半（界面明确提示：重指后新搭档看不到旧私密记录）。
- 提醒开关（常驻，见第 8 章）。
- 退出家庭圈（圈主无此项，界面注明「圈主不可退出」）。

## 7. 上传与弱网策略

方案定稿：**本地队列自动补传**（T7 决议，[调研详情](../research/weak-network-upload.md)）。目标场景：旅行中弱网/离线也能完成打卡，联网后自动出现。

### 7.1 关键事实（决定设计的）

- `wx.chooseMedia` 的 `tempFilePath` 小程序关闭后即失效 → **选中后立即 `wx.saveFile` 转持久路径**（与草稿策略共用这一层）。
- `wx.cloud.uploadFile` **无内置重试**，超时/断网直接报错 → 自建重试。
- 本地文件系统上限 200MB、storage 上限 10MB → 队列只存**元数据**，文件本体在文件系统。
- 小程序切后台 5 秒后网络请求被中断 → 后台不指望传完，回前台再补。

### 7.2 队列行为规则

- **入队时机**：点「发布」才开始传（草稿阶段只持久化不传）。发布时：全部媒体入 pending 队列 → 开始并发上传（并发 3）。
- **重试**：失败按指数退避（1s/2s/4s/8s…），最多 3 次；超限或遇断网类错误（`network is down`、超时）转 pending 挂起。
- **补传触发**：`app.onShow` + `wx.onNetworkStatusChange`（恢复联网即触发）。
- **提交记录**：全部媒体 fileID 到齐后才调 `publishRecord`；记录提交失败（非网络类）保留队列并提示。
- **幂等**：`cloudPath` 用 `{openid}/{timestamp}-{随机串}` 保证唯一；上传成功但 `publishRecord` 未达的场景靠队列里的 `recordId?` 字段防重发（已发过则只补传文件、不再建记录）。
- **用户感知**：发布页立即返回首页；首页顶部显示「1 条待同步」小状态条，补传成功后消失。**不做**错误弹窗轰炸，失败只体现在状态条点击后的说明里。
- **清理**：上传成功即 `wx.removeSavedFile` 本地文件；发布成功的草稿一并清除。

### 7.3 明确不做的

- 分块/断点续传（官方 uploader 库）——媒体 ≤ 压缩后几 MB，用不上
- 后台自动上传（不可靠且没必要）
- 跨设备草稿同步

## 8. 通知策略

定稿 = **微信推送 + 站内红点兜底**（ADR [0004](../adr/0004-notification-strategy.md)，[订阅消息调研](../research/subscribe-message.md)）。

### 8.1 推送（一次性订阅消息）

- **模板**：公共模板库申请「内容提醒/家庭内容提醒」类。**模板若审核不过：MVP 以纯红点形态先上线，推送留接口后补，不阻塞开发**（这是预设好的降级路径）。
- **内容**：作者昵称 + 地点名 + 吐槽首句截断；点击直达记录详情页。
- **节奏**：每条即推。唯一聚合：同一作者 1 分钟内连发多条只推最后一条。
- **授权额度**（个人主体只有一次性订阅，1 次授权 = 可发 1 条）：
  - 发布成功后引导一次（动机最强时刻，引导勾选「总是保持以上选择，不再询问」）；
  - 设置页常驻开关（关闭 = 不再请求授权也不再发）；
  - 每次打开小程序在**自然点击点静默续授权**（已勾选后调用不再弹窗，白攒额度）。注意 `wx.requestSubscribeMessage` 必须在用户点击的同步回调里调，不能放 onLoad。
- **降级**：额度耗尽（错误码 43101）**静默失败**，绝不提示发布者「谁没收到」。
- **隐私与权限联动**（云函数 `sendReminders` 内过滤）：
  - 「仅我俩」→ 只推 `pairIds` 两人，且用**模糊文案**（「你的另一半发了一条仅你可见的动态」——不带地点不带摘要，防止服务通知列表泄露）；
  - 「仅自己」→ 不推；
  - 退出/被移除成员 → 不推；
  - 作者本人 → 不推自己。

### 8.2 红点兜底

首页「N 条新回忆」红点条（6.2 节），数据来自 `bootstrap.unreadCount`。推送是增强不是依赖——推送全挂时产品依然完整可用。

## 9. 实现顺序

垂直切片：**每个阶段以「手机上可用」收尾**。难度 ★☆☆–★★★；不给工时预估（新手速度方差太大，估了只会焦虑）。每阶段列「易卡点」——新手最容易卡住的地方，提前有心理准备。

> 上线节奏（T6 决议）：**阶段 2 完成后就拉女友真实使用 2–4 周**，跑顺后再进父母。阶段 3–5 期间二人组就是真实用户。

### 阶段 0：环境搭建 ★☆☆

**做什么**：注册小程序（个人主体，类目见第 10 章）、开通云开发环境、装微信开发者工具、跑通 Hello World 并**真机预览**。

**验收**：手机上打开自己的小程序；云开发控制台能看到环境。

**易卡点**：AppID 与测试号的区别（用正式 AppID）；云开发「环境 ID」不是 AppID，调用时要填对。

### 阶段 1：单用户打卡闭环 ★★☆

**做什么**：onboarding（仅「创建家庭圈」入口，邀请码入口留占位）→ 发布页简化版（媒体 + 文字 + 星级 + 选点；可见范围/参与者/语音/折叠区全部不做，`visibility` 恒 `family`）→ 直传云存储 → `publishRecord` 落库（地点按 poiId 归并）→ 简版列表 + 简版详情（大图 + 文字 + 星级）。

**验收**：手机上打卡一家店（拍照 + 写字 + 打分），列表看到，点开详情看到大图；再打卡同一家店，归并为同一地点。

**易卡点**：云函数部署与调用权限；`wx.chooseMedia` 返回结构；fileID 与临时链接（`getTempFileURL`）——**图片显示必须用临时链接或 `<image src="cloud://...">`**。

### 阶段 2：家庭圈与权限 ★★☆

**做什么**：邀请码全流程（生成/作废/入圈）+ 成员管理（自退/移除/成员上限）+ 「另一半」指定 + 可见范围三档（发布页折叠区 + 三选一弹层）+ 参与者多选 + `pairIds` 快照固化 + 全读路径可见性过滤（4.6 节规则）+ 编辑/删除（能见即可改删）+ 设置页 + 补记时间。

**验收**：两台手机：女友凭码入圈；她发的「仅我俩」你能看、家庭档都能看；你移除一个测试账号后它再也看不到；改一条别人的记录能保存；补记昨天的记录时间正确。

**易卡点**：可见性过滤必须在**每个**读函数里都做（漏一处就漏数据）；`pairIds` 是创建时快照不是引用；云函数里 join 昵称头像。

### 阶段 3：浏览侧完整版 ★★☆

**做什么**：足迹列表（地点卡片：封面拼图/类型/均分/次数/情绪徽章）+ `listPlaces` 聚合 + 地点页（统计条 + 记录列表）+ 相册式详情（翻页 + 语音条播放）+ 地图段控视图（markers + customCallout）+ 空状态 + 红点条（`lastReadAt`/`markRead`）。

**验收**：同店 3 次打卡后卡片显示「3 次」、均分正确；地图一店一 marker、callout 信息正确；语音能播能停；新记录红点出现、点击后消。

**易卡点**：`<map>` markers 的 id 必须是数字（placeId 字符串要映射）；customCallout 需要置顶层级配合；封面拼图用 CSS grid 即可不必上 canvas。

### 阶段 4：弱网队列与草稿 ★★★

**做什么**：选中即 `saveFile` 持久化 → 发布时上传队列（7.2 节全部规则：并发 3、指数退避、3 次转挂起、onShow/联网补传、幂等 cloudPath）→ 草稿策略（6.5 节：全量保留、恢复失败置空）→ 首页「待同步」状态条。

**验收**：飞行模式打卡一条（拍照+文字+选点），发布后首页出现「1 条待同步」；恢复网络打开小程序，几秒内自动补传成功、状态条消失、记录可见；填一半杀掉小程序再打开，发布页内容都在；发布成功后 storage 里草稿被清。

**易卡点**：`tempFilePath` 与 `savedFilePath` 的转换时机（saveFile 后原 temp 路径失效）；切后台 5 秒中断——不要在后台指望传完；storage 里只放元数据别放 base64。

### 阶段 5：通知 + 收尾 ★★☆

**做什么**：申请订阅消息模板 → `sendReminders`（可见范围过滤 + 模糊文案 + 43101 静默 + 1 分钟去重）→ 发布成功后授权引导 + 设置页开关 + 打开时静默续授权 → 详情页落地（推送点击直达）→ 按第 10 章上线清单提交审核。

**验收**：双机：互发记录对方收到推送、点击直达详情；「仅我俩」收到的是模糊文案；设置里关掉提醒后不再收到也不再被请求授权；手动把额度耗尽（连续发几条不授权），发布不报任何错。

**易卡点**：模板类目与审核（10.3 节）；`requestSubscribeMessage` 必须在点击同步回调里；43101 是 fail 回调里的 `errCode`，不是异常。

## 10. 上线清单

### 10.1 类目选择

个人主体可选类目不含「社交」——选**工具类**（如「工具-笔记/记录」）。审核材料与页面文案中**避免出现「社区」「社交」「分享给好友」类表述**，定位为「家庭相册/记录工具」。

### 10.2 隐私与权限声明

- 《小程序用户隐私保护指引》中声明收集：**位置信息、头像昵称、选择的照片/视频/语音**（均为用户主动提供，用途写「记录与展示」）。
- `app.json` 声明 `requiredPrivateInfos: ["getLocation", "chooseLocation"]`（或 `choosePoi`），并在后台申请 `wx.getLocation` 接口权限（使用场景写「打卡时选取当前位置附近的地点」）。
- 首次使用相机/相册/麦克风/定位时按微信平台弹窗引导，被拒后给「去设置开启」的引导入口（T5 原型已有降级引导设计）。

### 10.3 订阅消息模板

公共模板库找「内容提醒」类；审核若不过：走 8.1 节预设的降级路径（红点先上线、推送留接口），**不要卡在等模板上**。

### 10.4 发布流程

体验版（开发者 + 女友为体验成员）→ 提交审核（首审通常 1–7 天）→ 全量发布。域名白名单无需配置（云开发免域名）。

### 10.5 数据导出 runbook（T11 决议：纯手动，开发量零）

**用途**：长期留档 / 停维护时带走数据 / 涨价时迁移。

1. **数据库**：云开发控制台 → 数据库 → 各集合 → 导出 JSON（全量），存本地电脑一份；
2. **媒体**：云开发控制台 → 存储 → 全选下载（量大时用 COSBrowser 工具登录拉取）；
3. 归档到一个文件夹（`backup-YYYY-MM-DD/`），双份存储（本地 + 移动硬盘/网盘）；
4. **节奏**：不设自动化、不定时——想留档时手动跑一遍。短期兜底靠云开发自带每日备份/7 天回档。
