# 微信小程序订阅消息能力与频次限制调研

## 调研目的
为"家庭成员发布新内容后互相通知"功能提供技术可行性依据，调研微信小程序订阅消息的能力范围、频次限制、模板申请要求、个人开发者限制以及云开发侧的实现方式。

**调研日期**：2026-08-14
**调研来源**：微信官方文档、腾讯云 CloudBase 官方文档

---

## 1. 订阅消息类型与适用范围

### 1.1 新版一次性订阅消息（Beta）

**特点**：
- 无需用户在弹窗中主动订阅即可向用户下发消息
- 获取 code 的两种方式：
  - 将微信支付订单号作为 code（支持购物、快递、保险、餐饮、酒店、交通等多个业态）
  - 通过前端 button 组件获取 code（open-type="liveActivity"）

**限制**：
- 平台定义模版，开发者根据自身业务选择模版进行接入
- 模板有对应类目要求，符合类目要求的小程序可在公共模版库看到
- 不支持通过 wx.requestSubscribeMessage 向用户申请订阅该模版

**来源**：[新版一次性订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message-2.html)

### 1.2 一次性订阅消息（用户通过弹窗订阅）

**特点**：
- 开发者调用 `wx.requestSubscribeMessage` 后向用户展示弹窗
- 用户可打开自己想要接受的消息开关
- 用户订阅后，开发者可不限时间地下发一条对应的服务消息
- 每条消息可单独订阅或退订

**触发方式**：
- 必须在用户点击事件的同步回调里调用
- 不能放在 onLoad 或异步 await 之后，否则会直接报「请求被拦截」

**来源**：[小程序订阅消息（用户通过弹窗订阅）开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)

### 1.3 长期订阅消息（用户通过弹窗订阅）

**特点**：
- 用户订阅一次后，开发者可长期下发多条消息
- 分为「不限频」与「限频」两种类型
- 限频类型支持按照预设频次（如每日一次、每月一次等）向用户下发消息

**开放范围**：
- **仅向政务民生、医疗、交通、金融、教育等线下公共服务开放**
- 后期将逐步支持到其他线下公共服务业务
- 限频消息暂向金融等指定行业开放

**来源**：[小程序订阅消息概述](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message-overview.html)

### 1.4 设备订阅消息

**特点**：
- 属于长期订阅消息类型
- 需要完成「设备接入」才能使用
- 用于在设备触发某些需要人工介入的事件时（如设备发生故障、设备耗材不足等）向用户发送消息通知

**来源**：[小程序订阅消息概述](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message-overview.html)

## 2. 频次与条数限制

### 2.1 前端调用限制

| 项目 | 限制值 |
|------|--------|
| **单次调用最多订阅条数** | 3条消息（tmplIds 最多为3个） |
| **平台版本要求** | iOS 7.0.6+、Android 7.0.7+ |
| **弹窗行为** | 用户勾选"总是保持以上选择，不再询问"后，下次调用不弹窗 |

**来源**：[小程序订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)

### 2.2 服务端发送限制

| 小程序类型 | 每日发送上限 |
|-----------|-------------|
| **开通支付能力的小程序** | 300万次/日 |
| **未开通支付能力的小程序** | 100万次/日 |

**来源**：[小程序订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)

### 2.3 订阅额度规则

| 消息类型 | 额度规则 |
|---------|----------|
| **一次性订阅消息** | 用户每授权1次 = 服务端可发1条；再发一次需要再次授权 |
| **长期订阅消息** | 用户授权1次，服务端30天内可重复发，不消耗额度 |
| **设备订阅消息** | 类似长期订阅，但绑定设备 |

**来源**：[腾讯云开发订阅消息教程](https://docs.cloudbase.net/recipes/add-subscribe-message-cloud-function)

## 3. 模板申请流程与审核要求

### 3.1 申请流程

1. 登录微信公众平台（mp.weixin.qq.com）
2. 进入「功能 - 订阅消息 - 公共模版库」
3. 查询可以申请的模板
4. 如果没有合适的模板，可以申请添加新模板
5. 审核通过后可使用

**来源**：[小程序订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)

### 3.2 模板类目要求

**重要限制**：
- 模板有对应类目要求
- 符合类目要求的小程序可在公共模版库优先看到相应模版
- 删除小程序类目会导致对应订阅消息模板也被删除

**来源**：[新版一次性订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message-2.html)

### 3.3 个人开发者可用类目

根据官方文档，个人主体小程序开放的服务类目包括：

| 类目 | 具体服务 |
|------|----------|
| **生活服务** | 丽人服务、婚庆服务、家政服务 |
| **餐饮服务** | 餐厅排队（不包含外卖） |
| **旅游服务** | 出境WiFi租赁 |
| **工具** | 记账、日历、天气、办公工具、图片处理等 |
| **商业服务** | 律师、企业管理、会展服务、环保回收等 |
| **体育** | 体育培训、在线健身 |
| **交通服务** | 代驾服务（不包含顺风车、网约车） |
| **教育服务** | 教育信息展示（不含视频播放/直播） |
| **物流服务** | 查件、装卸搬运（不含寄件、收件） |

**限制说明**：
- 个人主体小程序的服务类目受到较多限制
- **不包含社交、电商、医疗等类目**
- 如需提供更复杂的服务，建议注册非个人主体的小程序账号

**来源**：[小程序开放的服务类目](https://developers.weixin.qq.com/minigame/product/material/)

## 4. 「家庭成员发布新内容」场景合规性分析

### 4.1 个人主体限制

**核心结论**：
- ✅ 个人主体小程序**可以使用订阅消息功能**
- ✅ 但主要限于**一次性订阅消息**
- ❌ 无法申请**长期订阅消息**（仅限政务、医疗、交通、金融、教育等线下公共服务）
- ⚠️ 需要在生活服务类目下寻找合适的模板

**来源**：官方文档及社区讨论综合分析

### 4.2 可用的模板类型

对于"家庭成员发布新内容"场景，个人主体可能可以申请的模板包括：

| 潜在模板 | 类目 | 可行性 |
|---------|------|--------|
| **生活服务-家政服务** | 生活服务 | ⚠️ 需审核确认 |
| **工具-信息提醒** | 工具 | ✅ 较为可行 |
| **自定义模板** | 依据类目 | ❓ 需要审核确认 |

**注意事项**：
- 个人主体可申请的模板范围有限
- 具体能否申请到"家庭内容提醒"类模板，需要提交审核后确认
- 可能需要将场景包装为"工具-信息提醒"等通用类型

**来源**：[小程序开放的服务类目](https://developers.weixin.qq.com/minigame/product/material/)

### 4.3 用户授权流程

**一次性订阅消息授权流程**：
1. 用户在小程序中点击某按钮触发事件
2. 调用 `wx.requestSubscribeMessage` 弹出授权窗口
3. 用户勾选想要接收的消息类型（最多3条）
4. 用户授权后，服务端可获得一次发送机会

**弹窗行为**：
- 用户勾选"总是保持以上选择，不再询问"后，后续调用不会弹窗
- 用户的选择将被保留，如需修改需在小程序设置中手动更改

**来源**：[小程序订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)

## 5. 云开发侧推送方式与计费

### 5.1 云函数调用方式

**使用 `wx-server-sdk`**：
```javascript
const cloud = require('wx-server-sdk');
cloud.init();

exports.main = async (event) => {
  const result = await cloud.openapi.subscribeMessage.send({
    touser: event.openid,
    templateId: event.templateId,
    page: event.page || 'pages/index/index',
    data: event.data,
    miniprogramState: 'formal', // formal/trial/developer
    lang: 'zh_CN',
  });
  return result;
};
```

**前置要求**：
- 必须使用 `wx-server-sdk`，不能用 `@cloudbase/node-sdk`
- 需要在 Cloudbase 控制台 → 环境设置 → 微信公众平台关联，把当前小程序 AppID 和当前 env 关联起来

**来源**：[腾讯云开发订阅消息教程](https://docs.cloudbase.net/recipes/add-subscribe-message-cloud-function)

### 5.2 配额与计费

**配额模型**：
- 微信云开发使用「基础套餐+按量付费」的计费模式
- 云函数调用 openAPI 属于资源点计费范围

**资源点换算**：
- 1,000 资源点 = 1 元

**免费额度**（个人版）：
- 每月 40,000 点/月

**来源**：[微信云开发计费说明](https://developers.weixin.qq.com/minigame/dev/wxcloud/billing/price.html)

### 5.3 错误处理与常见问题

| 错误码 | 原因 | 解决方案 |
|--------|------|----------|
| **43101** | 用户没订阅这个模板，或上次的「一次性订阅」已被消费过 | 正常业务路径，前端先 `requestSubscribeMessage` 拿授权 |
| **47003** | `data` 里某个字段超长，或字段名和模板对不上 | 比对模板字段名，严格按结构传值，超长字段截断 |
| **40037** | `templateId` 不存在或已删除 | 重新去公众平台获取最新的 templateId |
| **41030** | `page` 路径不存在 | 确保路径是已发布版本里有的页面 |

**来源**：[腾讯云开发订阅消息教程](https://docs.cloudbase.net/recipes/add-subscribe-message-cloud-function)

## 6. 对本项目的结论

### 6.1 技术可行性

**✅ 订阅消息功能对个人开发者可用**：
- 个人主体小程序可以使用订阅消息功能
- 主要限于一次性订阅消息
- 每日发送上限100万次（未开通支付能力）

**⚠️ 模板申请存在不确定性**：
- 个人主体可申请的模板范围有限
- "家庭内容提醒"类模板的审核结果不确定
- 可能需要包装为"工具-信息提醒"等通用类型
- **需要在微信公众平台实际提交申请后确认**

### 6.2 落地形态建议

**推荐方案：一次性订阅消息**

对于 4-6 人家庭圈的「有人发了新记录」通知场景：

**用户体验流程**：
1. 家庭成员A上传新内容（照片/视频/打分吐槽）
2. 系统提示A：其他成员还未开启通知，是否邀请他们开启？
3. A选择邀请 → 调用 `wx.requestSubscribeMessage` 弹窗（A为其他成员授权）
4. **问题**：这需要A为其他成员授权，不符合实际使用场景

**实际可行方案**：
1. 每个家庭成员首次使用小程序时，引导他们授权接收通知
2. 当其他成员发布新内容时，已授权的成员会收到订阅消息通知
3. 每次发送消息需要消耗一次授权额度

### 6.3 核心限制与应对策略

**限制1：一次性订阅每授权1次只能发1条**
- **应对**：引导用户在关键场景下多次授权，积累足够的发送额度
- **应对**：提供明显的授权入口，鼓励用户主动订阅通知

**限制2：用户需要频繁授权**
- **应对**：优化授权时机，在用户完成满意操作后引导授权
- **应对**：提供授权状态管理，让用户了解自己的授权情况

**限制3：个人主体模板审核不确定性**
- **应对**：准备多个备选模板方案
- **应对**：如审核不通过，考虑转为个体工商户或企业主体

### 6.4 最终结论

**订阅消息可以用于本项目，但存在以下现实限制**：

1. **技术可行**：个人主体小程序可以使用一次性订阅消息
2. **用户体验受限**：用户需要频繁授权，每次授权只能发送一条消息
3. **模板审核不确定**："家庭内容提醒"类模板能否通过审核需要实际测试
4. **管理成本较高**：需要管理每个家庭成员的授权状态和剩余额度

**推荐落地策略**：
- 先尝试个人主体+一次性订阅消息方案
- 如果用户体验或模板审核遇到问题，再考虑转为个体工商户主体
- 长期来看，如果产品发展良好，建议转为企业主体以获得长期订阅消息能力

## 7. 未能确认的事项

以下事项在官方文档中未能找到明确说明，标注为「未能从官方来源确认」：

1. **个人主体在"生活服务"类目下可申请的具体订阅消息模板列表**：
   - 官方文档没有明确列出个人主体在各类目下可申请的模板清单
   - 需要登录微信公众平台后台查看公共模板库才能确认

2. **"家庭内容提醒"类模板的审核标准**：
   - 官方文档没有明确说明此类模板的审核要求
   - 需要实际提交申请后根据审核结果确认

3. **一次性订阅消息授权额度的有效期**：
   - 官方文档没有明确说明用户授权后的额度是否有时间限制
   - 社区讨论认为长期有效，但缺乏官方明确说明

4. **订阅消息模板的字段长度限制详情**：
   - 官方文档有提及字段长度限制，但没有完整的字段类型与长度对照表
   - 实际开发中需要参考模板申请时的提示
